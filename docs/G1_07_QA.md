## 구현 내용

- `/dad/community`, `/daughter/community`: 각각 **샘플 게시글 3개**와 시연 주제 필터, 화면 내 검색(제목·발췌·본문), 시연 순서/제목 가나다순, 0건 결과/초기화. URL 검색어·게시글 원문 전송 없음.
- `/dad/community/[id]`, `/daughter/community/[id]`: 각 3개 ID의 읽기 전용 샘플 글 상세 및 샘플 댓글. 기존 홈 프리뷰 2개는 동일 fixture ID/제목을 사용하여 역할별 데이터 일관성 유지. 다른 역할의 글 ID, 비정상/없는 ID는 정확히 404.
- `/dad/community/new`, `/daughter/community/new`: 실제 작성이 아닌 **React 컴포넌트 메모리에서만 작동하는 입력·미리보기·전체 지우기** UI. 버튼은 `type="button"`, HTML `<form>`, POST, fetch, API, action, server mutation 없음. JS 없이 게시되거나 GET 쿼리로 입력값이 전송될 수 있는 제출 경로가 존재하지 않음.
- React는 입력값을 텍스트로 이스케이프 렌더링(`dangerouslySetInnerHTML` 금지). 타이틀 80자, 내용 500자로 제한. 미리보기는 **게시·저장 완료**로 안내하지 않음. 이탈/리로드 시 React 메모리 해제, 복구 불가임을 페이지에 명시.
- `community-dad.ts`와 `community-daughter.ts`는 완전히 별개의 읽기 전용 합성 fixture; `community-catalog.ts`는 `space`와 exact ID를 동시에 조회. 공통 화면은 판별된 `CommunityDemoProps`만 소비. 닉네임·실작성자 ID, 학교·주소·연락처·실제 개인 사연·이미지/미성년자 사진·실댓글/응답수/타임스탬프 없음.
- 아빠는 블루그레이/아이보리, 딸은 크림·차콜·베리와 `SIDE B / AFTER HOURS` 편집 레이블로 기존 두 공간 미감 유지. 4탭, 화면 재선택, 기존 9개 합성 에디토리얼 상세 기능 보존.
- 자기신고식 `dad/daughter`는 **탐색 UX만** 의미. 연령/가족관계/작성 권한 인증이 아님. 웹 공개 게시판, 민감 원문·타 공간 사연 공유, 신고 처리는 **G2 심의 전 금지**.
