# G0-04 보안 경계·테스트 계획 v1.0

> 상태: **사전 설계 문서**. 실제 테스트 수행·운영 보안 검증·법률 자문 완료가 아님.  
> 근거: [기술 구조](./TECHNICAL_ARCHITECTURE.md), [데이터 계약](./DATA_CONTRACTS.md), [개발 계획](./DEVELOPMENT_PLAN.md)  
> G0-04에서 소스코드/DB/Auth/실게시글/공개 서비스 배포를 하지 않는다.

## 1. 위협 모델과 보호 대상

서비스는 두 독립 공간과 익명 커뮤니티를 목표로 한다. 청소년 이용자가 포함되므로 일반 익명 게시판보다 신원 추정·그루밍·원문 노출·실제 권한 오인의 위험이 크다.

| ID | 위협 / 실수 | G1 Phase 1 대응 | G2 이후 필요한 추가 보호 |
| --- | --- | --- | --- |
| SEC-01 | UI 아빠/딸 선택으로 다른 게시판 쓰기 권한 우회 | **실제 쓰기 엔드포인트 없음**. 전부 합성 데이터 | 신뢰 가능한 별도 자격 검증, 기본 거부 server authz + RLS 부정 테스트 |
| SEC-02 | 미성년자 실제 게시물/연락처 노출 | 실사용자 데이터 입력·전송/장기 저장/공개 금지, DM 미제공 | 안전 규칙·PII 탐지·신고·차단·관리자 조치 |
| SEC-03 | 공통 ‘서로의 시선’ 원문 역추적 | 별도 합성 또는 승인된 **편집 집계만** 사용. 원문 ID/링크 없음 | 공개 동의 확인·동의 철회·소표본 보호·편집 감사 |
| SEC-04 | 쇼핑·SNS 최신성 허위 주장 | 시연 라벨, 검증/만료 상태 분리 | 공식 출처, 승인 워크플로, 만료·정정 처리 |
| SEC-05 | 비밀키·실제 계정 데이터 유출 | API/비밀키/계정 기능 **도입하지 않음** | 서버 전용 secret 관리/회전, DB 접근 정책 |
| SEC-06 | XSS 및 악성 링크 | 합성 문장만. 사용자 HTML 실행·unsafe injection 없음 | 서버 입력 검증, HTML escape, 검증된 외부 URL |
| SEC-07 | CSRF/권한 요청 위조 | 쓰기 API/폼 submit 서버 처리가 없음 | 서버 mutation/세션 도입 시 CSRF·SameSite·origin 검사 |
| SEC-08 | 스팸·괴롭힘·성적 접근/그루밍 | 실사용자 작성/접촉/사진 업로드 기능 없음 | 운영자 상시 신고 대응, 속도 제한, 제재, 위기대응 정책 |
| SEC-09 | 영리 목적 청소년 행동 추적 | 광고/분석/외부 추적 스크립트 도입하지 않음 | 합법적 최소 수집 및 정책/광고 검토 |
| SEC-10 | 역할 UX 저장을 나이·가족관계 인증으로 오해 | localStorage 한 개의 dad/daughter 탐색 값만 | 별도 검증 절차; 서버는 클라이언트 값 신뢰 금지 |

**정책 분리:** 단순히 브라우저에서 각 공간을 선택할 수 있다는 것과 아빠/딸 **검증 계정만 글을 쓸 수 있다는 주장**은 다르다. G2에서 적법한 역할 확인 방식이 결정되지 않으면 실제 쓰기 서비스는 보류한다.

**연령:** 초기 공개 작성은 만 14세 이상 대상으로만 검토하며 만 14세 미만은 적법한 법정대리인 동의·확인 체계 전까지 제공하지 않는다. 실제 나이/법률 요건·동의 방식·처리 항목은 출시 전 전문 검토 대상으로 남긴다.

## 2. 데이터 접근 및 네트워크 금지선

| 영역 | G1에서 읽기 | G1에서 쓰기 | 도입 금지 |
| --- | --- | --- | --- |
| 정적 편집 합성 fixture | 공개 읽기 가능 | 운영 정적 파일 변경은 Git PR만 | 실시간 무단 스크래핑·자동 게재 |
| 운영자 작성 투표/토너먼트 fixture | 고정 질문·선택지·대진을 정적 검수 후 공개 | 지정 운영자의 리뷰된 콘텐츠 변경만; 이용자 응답은 세션 내 상태만 | 이용자 작성 질문/선택지·자유 입력·응답 저장/집계·관리자 CMS/Auth 미승인 |
| 아빠·딸 합성 커뮤니티 | 시연 UI에서 읽기 | React 상태 임시 입력만 | HTTP POST, DB write, 로컬 장기 저장 |
| 운영자 작성 고정 선택지 투표/토너먼트 | 검수된 정적 fixture; 이용자 선택은 세션 한정·비저장·비집계 | 이용자 질문/선택지/대진 생성, 자유 입력, 장기 응답 기록·집계 불가 | 실응답 수·순위 통계·작성자 ID·원문 링크 |
| 역할 마지막 선택 | 브라우저 선호 값 읽기 | 해당 브라우저 선호 키만 | 서버 권한·인증/실명과 연결 |
| 분석/광고/서드파티 | 없음 | 없음 | 행동 추적 스크립트·SDK |
| 미성년자 계정 정보 | 없음 | 없음 | 가입·개인정보 수집·사진/위치·DM |

코드 도입 후에는 개발자 도구 Network 검사로 **의도하지 않은 서버 mutation/외부 요청이 없는지** 확인한다. 콘솔/서버 로그에 입력한 글이 남지 않게 테스트한다. 개발 서버 기본 정적 GET 요청은 존재할 수 있으므로 ‘네트워크 요청 자체가 0’이라고 잘못 주장하지 않는다.

## 5. 향후 외부 서비스 의존과 운영 정책

Phase 1에서는 Supabase 접속, 실DB/Auth, Vercel 공개 배포, 외부 이미지 무단 가져오기, 유료 API 사용을 하지 않는다. 의존성을 도입하게 되는 G2에서 보안 책임이 있는 서비스 측에서 비밀키·운영 권한을 관리하며 프론트 환경 변수로 관리자 키를 전달하지 않는다.

데이터가 입력될 경우 운영자 검토, 신고·제재, 게시글 삭제·보존·동의 철회와 법적 연령 기준을 실제 서비스 전에 검증해야 한다. **현재 문서만으로 안전한 실운영이 가능하다고 주장할 수 없다.**

## 6. 다음 작업 G1-01

G0 문서 게이트가 모두 종료된 후 사용자 버튼으로 시작한다. 독립 브랜치에서 **최소 Next.js scaffold + TypeScript/Tailwind + 검사 스크립트**만 구성한다. 구현 버전 및 공식 설치 지침을 확인한 뒤 실제 명령·로그·실패 내역을 남긴다. G1-01에서 랜딩 기능이나 게시판 기능을 한 번에 만들지 않는다.
