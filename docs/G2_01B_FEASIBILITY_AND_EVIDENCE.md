# G2-01B 편집형·커뮤니티 대안 사업성 및 검토 증거 패키지 v0.1

> 작성일: 2026-11-11 (KST)  
> 용도: 법률·개인정보·아동 안전·운영 전문가 및 사업 책임자 사전 검토용  
> 상태: 문서 초안만 작성. 외부 발송·자문·계약·운영 승인 없음. G2-01·02·03 HOLD 유지.

## 1. 요약과 결정 경계

초기 이용자가 적을 때 빈 게시판을 채우려고 사용자 작성 게시판을 먼저 열지 않습니다. 현재 승인된 초기 방향은 편집자가 출처·권리·확인일을 관리하는 콘텐츠와 운영자가 직접 작성하는 고정 질문·선택지·토너먼트입니다. 질문과 토너먼트는 정적 시연 fixture이며 응답을 저장·집계하지 않습니다.

이 문서는 A(편집형), B(동의·계약을 거친 기고), C(제한형 실사용자 커뮤니티), D(아빠/딸 역할 증명 커뮤니티)의 비용 항목·위험·필요 증거를 비교합니다. 측정된 시장 수요·발생률·공급업체 가격이나 법적 결론은 아닙니다. 실제 커뮤니티의 필요성은 방문자 수 하나로 판단하지 않으며, 수요·운영 책임·예산·안전 통제·법률 의견을 각각 증거로 확인하고 별도 승인합니다.

**현재 권고:** A를 계속 운영하고 실제 UGC·댓글·회원 계정·응답 저장/집계·역할 증명 기능은 출시하지 않습니다. B는 미성년자 기고자 보호, 개인정보 최소화, 이용허락·동의·철회 절차가 마련된 후 검토합니다. C와 D는 각 Gate 증거를 갖추기 전까지 차단합니다. D는 가족관계나 성별 확인을 위해 과도한 증명 자료를 수집할 위험이 커서, 검증 가능한 최소수집 대안이 입증되지 않으면 채택하지 않습니다.

### 초기 활성화 원칙

- 빈 글 목록·가짜 이용자 수·합성 댓글을 실제 활동처럼 표시하지 않습니다.
- 편집 콘텐츠 끝의 대화 질문은 가능하지만, 실제 입력·전송 기능이 없다면 화면 내 시연임을 알립니다.
- 비식별 집계가 별도 승인되기 전에는 응답을 추적해 수요를 증명하지 않습니다. 현재는 인터뷰 계획, 화면 탐색성 검토, 외부 전문가 검토, 승인된 절차의 자발 피드백 같은 증거만 검토합니다.
- 게시 기능은 트래픽이나 회원 수 기준 하나만으로 자동 개설하지 않습니다.

## 3. 운영량과 비용 산정 프레임

실제 인건비, 신고율, 게시량, 공급업체 견적은 없습니다. 특정 원화 비용이나 필요 인원 수를 예산처럼 제시하지 않습니다.

### 3.1 월 비용 항목

월 운영비는 편집/검토 인력 + 담당·대기·대체 + 법률·개인정보·아동 안전 자문 + 기술·보안 + 연령/역할 확인 위탁 + 사용자 지원 + 사고 대응 준비금으로 나눠 산정합니다.

| 묶음 | 실제 산정에 필요한 자료 | 확인 증거 |
| --- | --- | --- |
| 편집(A/B) | 주간 발행량, 조사·출처·권리 확인·교정·정정 시간, 대체 인력 | 역할별 업무 시간 표본, 인건비/외주 계약, 권리대장 |
| 사전검토/모더레이션(C/D) | 신규 글·댓글·신고·재검토·이의제기 수 및 평균 처리시간 | 합성 부하 테스트, 정책별 모의 사례 시간 측정 |
| 담당·대기 | 운영시간, 휴일/야간 사건 에스컬레이션, 2인 승인, 휴가·부재 대체 | 승인 근무표, 직무기술서, 대체 담당자·승계 훈련 |
| 전문 자문 | 플랫폼 지위, 약관·처리방침, 동의/연령, 사고별 자문 | 범위·산출물이 있는 제안서, 계약, 승인 예산 |
| 보안·인프라 | 계정/API/저장/로그/백업/접근통제, 취약점 점검, 복구·삭제 | 데이터 흐름, 보안 점검 제안서, 복구/삭제 시험 |
| 역할/연령 확인 | 단가 외 오류 재검토·이의제기·삭제·접근성 비용 | 공급자 자료, 위탁 계약, 하위처리자/국외이전, 보존·삭제 증거 |
| 신고·지원 | 채널 확인, 사건 분류, 이용자 안내, 결과 및 이의제기 | 담당 조직, 업무시간, 교육, 훈련 결과 |
| 사고·보험 | 포렌식, 피해 통지·구제, 보험 가능성 | 대응 계약, 보험 약관·면책, 사고 연락망 |

### 3.2 처리량 계산식과 해석

- 일일 직접 검토시간 = (신규 글 수×글당 평균 검토 분 + 댓글 수×댓글당 평균 검토 분 + 신고 수×신고당 평균 처리 분 + 이의제기 수×재검토 평균 분) ÷ 60
- 일일 총 작업시간 = 직접 검토 + 정책/품질회의 + 교육 + 기록/보고 + 사고 대응 + 인수인계·휴게 부담.
- 월 인력 원가 = 업무별 유급시간×확인된 실제 원가 + 교대/대기/대체/휴가 비용 + 법률·개인정보·보안·위탁·도구 비용.
- 연속 24시간 운영의 담당 좌석 하나는 주당 168시간의 커버리지가 필요합니다. 이것은 한 사람이 주 168시간 일해야 한다는 뜻이 아니며, 실제 인력과 원가는 근로시간·휴게·휴가·이중 승인·대체 인력·계약으로 산정해야 합니다.
- A의 편집 노동과 C/D의 안전 검토·사건 대응을 동일 비용으로 비교하지 않습니다. 정기 검토량이 적어도 중대 사건은 예측하기 어려울 수 있습니다.
- 작업량 표본은 합성 콘텐츠와 훈련 데이터로만 측정합니다. 견적을 위해 실제 청소년 게시물을 수집하지 않습니다.

## 4. 연령·역할 확인과 신뢰 경계

아빠/딸 공간 선택은 화면 개인화이며 신원·연령·친족관계 인증이 아닙니다. 역할 버튼 클릭만으로 보호된 쓰기 권한이나 안전성이 입증되지 않습니다.

### 전문가 확인 질문

1. “10대 딸”을 포함하는 서비스에서 연령(<14, 14~18, 성인)별로 어떤 법률·고지·동의 요구가 적용되는가? 대상 서비스 판단과 기능별 처리를 분리해 검토해 주십시오.
2. 개인정보 보호법 제22조의2 및 시행령 제17조의2가 적용되는 구체적 조건은 무엇인가? 일반 열람, 계정, 게시, 사진, 투표 저장을 구분해 주십시오.
3. 만 14세 미만 법정대리인 동의·확인, 14~18세의 정보 처리 및 보호자 관련 요구를 어떻게 적용해야 하는가? 법정 기준과 권고를 분리해 주십시오.
4. 아빠/딸 역할 제한이 꼭 필요한가? 가족관계증명서·신분증·학생증·얼굴/음성·생체정보·학교 정보 없이 달성할 대안은 무엇인가?
5. 외부 확인 공급자를 쓴다면 운영자/수탁자 역할, 처리 근거, 최소 수집, 보존·삭제, 하위처리자, 국외 이전, 사고 통지, 오인증 이의제기를 어떻게 문서화해야 하는가?
6. 공급자 판정 결과만 받더라도 로그·쿠키·기기정보·메타데이터 결합으로 연령/역할 추정이 가능한가? 이를 어떻게 시험하는가?
7. 보호자가 계정·게시물에 접근하는 기능이 안전/사생활에 미치는 영향은 무엇인가? 가족 갈등·강압 가능성이 있을 때 보호자 연락을 자동 실행하지 않도록 어떤 절차가 필요한가?
8. 최소수집 방식과 오인증 구제 기준이 입증되지 않는다면 D를 배제하고 A/B 또는 역할 구분 없는 정보 제공으로 제한해야 하는가?

### 공급자 자료 요청 목록

공급업체는 선정하지 않았습니다. 후보가 생기면 동일한 질문으로 자료를 받습니다.

- 데이터 흐름도, 수집 항목, 판정 신호, 운영자에게 돌려주는 결과값
- 오류율의 대상 모집단·검증방법·연령대별 한계·독립 감사 결과
- 원본/생체/신분자료 처리 여부, 보유·삭제 시점, 백업/로그 예외, 삭제 확인
- 보안 인증, 침투 테스트 요약, 취약점 수정, 사고 통지 연락 체계
- 위탁 계약, 하위처리자와 변경 통지, 국외 저장·접근 위치 및 이전 근거
- 열람/정정/삭제/철회/이의 요청 지원, 오류 재심사와 대체 수단
- 청소년·장애 접근성, 기기 미보유 이용자 대체 절차, 차별 영향 검토
- 가격표 외 최소 이용량, 추가 검토/사고 비용, 종료 시 반환·삭제 조건
- 공급자 홍보 문구 외 독립 법률 검토. 공급자 판정만으로 역할 인증이나 법률 적합성을 인정하지 않습니다.

## 6. 모의 사고 대응 훈련안

60~90분 탁상 훈련으로 설계할 수 있으나 시간은 제안일 뿐 법정 기한이나 운영 약속이 아닙니다. 가상 신고·계정·로그만 사용하고 실제 청소년·게시물·연락처·사진을 사용하지 않습니다. 훈련안은 실제 대응 역량이나 준비 완료를 증명하지 않습니다.

### 시나리오: 외부 연락 유도 신고와 역할 경계 노출 제보

가상 신고는 딸 공간의 성인 계정이 학교/전화번호를 요구하고 다른 앱으로 대화를 옮기자고 했다는 내용만 담습니다. 이어 운영자 계정 비정상 접근과 딸 공간 일부 화면이 아빠 역할 계정에서 보였다는 가상 제보를 전달합니다. 성적·식별·실제 개인정보는 묘사하지 않습니다.

### 진행 단계

1. **접수와 분류:** 접수 확인자, 사건 책임자, 즉시 숨김/접근 차단 권한, 아동에게 추가 개인정보를 묻지 않는 절차를 확인합니다.
2. **청소년 안전:** 위험 접촉을 멈추는 조치, 어린 이용자에게 제공할 쉬운 안내, 보호자 연락의 필요성과 안전성을 누가 검토하는지 확인합니다. 자동 연락은 하지 않습니다.
3. **보안/개인정보 확인:** 실제 노출 여부·항목·범위·시점·원인을 확인할 최소 로그와 접근 승인자를 정합니다. 계정 격리, 권한 회수, 추가 노출 방지 담당자를 확인합니다.
4. **법률 판정:** 법률/개인정보 담당자가 개인정보 유출 통지·신고 조건과 시점, 망법·전기통신사업법·청소년성보호법상 적용 가능성을 현행 조문에 대조합니다. 법적 의무, 운영 목표, 자발 조치를 별개로 기록합니다.
5. **최소 증거 보존:** 보존 승인자·기간·접근 이력과 삭제/백업/로그 간 충돌의 결재자를 정합니다. 이용자 고지 사항도 검토합니다.
6. **통지·복구:** 이용자·보호자·감독기관·공급자 통지 여부, 사실관계 승인자와 후속 정정 담당자를 정합니다. 구체적인 법정 기한은 전문가가 사실관계에 맞춰 확인합니다.
7. **연속 운영:** 담당자 부재·공급자 미응답 시 대체 담당과 기능 정지 권한자를 확인합니다.

### 산출물과 통과 기준 후보

- 타임라인, 가상 식별자, 결정자·근거, 에스컬레이션, 차단·복구 기록을 작성합니다.
- 단일 담당자 의존, 법률 신고 기준/시점 미숙지, 보호자 연락 위험 검토 누락, 과도한 로그 접근, 보존/삭제 승인자 부재, 책임을 미성년자에게 전가하는 안내는 발견 사항으로 기록합니다.
- 사전 승인된 책임자·보호조치·법률판정 경로·기록 기준이 있고 참가자가 실행 가능한지 평가합니다. 이 초안만으로 통과 판정하지 않습니다.
- 발견 사항마다 담당자, 증거, 기한, 재시험 기준을 지정합니다. 중대한 발견이 해결되지 않으면 관련 Gate를 HOLD합니다.
- 실제 훈련과 전문가 검토는 별도 실행이 필요합니다. 이 문서 병합은 훈련 실시나 운영 승인이 아닙니다.
