## 1. 토너먼트 선택 후 키보드 탐색 연결

**우선순위: 높음 / 구현 구조상 위험, 브라우저 재현 필요**

근거: [operator-activities.tsx](https://github.com/jkd04255/appa-wa-ddal/blob/52b41d7f49421358ba343f7c7feedf2ca6348b9d/src/components/perspectives/operator-activities.tsx)

현재 버튼은 보기 문자열을 React key로 사용한다. 선택하면 `picks`가 바뀌면서 다음 대진의 버튼이 생성된다. 준결승에서 다음 준결승으로 갈 때는 앞 단계의 두 보기가 모두 사라진다. 우승 결과에서는 버튼 영역 전체가 결과 영역으로 교체된다. 컴포넌트에는 focus/ref 처리나 전환 후 초점 대상이 없다.

초점을 가진 요소가 제거되면 사용자가 다음 단계 위치를 놓칠 수 있다. `aria-live`는 변경 내용을 알리는 역할이며 키보드 초점 이동을 대신하지 않는다. 실제 브라우저별 초점 결과는 아직 측정하지 않았다.

제안:

- 사용자가 선택했을 때 다음 단계 이름(예: ‘준결승 2 · 2/3’)으로 초점을 옮긴다.
- 우승 시 결과 안내, 재시작 시 첫 단계 안내로 이동한다.
- 최초 진입·새로고침에는 초점을 강제로 이동하지 않는다.
- 초점 표시를 눈에 보이게 하고 고정 하단 메뉴가 가리지 않는지 확인한다.
- 자동 알림과 초점 이동이 같은 내용을 반복 읽지 않도록 실제 스크린리더로 조정한다.

수용 기준: 아빠/딸 양쪽에서 Enter·Tab만으로 3회 선택 → 결과 → 재시작을 두 차례 이어갈 수 있어야 한다. 320px와 데스크톱, 재진입·새로고침을 포함한다. 선택 비저장·비집계 조건은 유지한다.

## 2. 발견 목록 상세 링크를 구별할 수 있게 변경

**우선순위: 중간 / 같은 링크 이름을 소스로 확인**

근거: [discovery-content.tsx](https://github.com/jkd04255/appa-wa-ddal/blob/52b41d7f49421358ba343f7c7feedf2ca6348b9d/src/components/daughter/discovery-content.tsx)

각 카드에는 서로 다른 h2 제목이 있으나 링크 본문은 모두 ‘이야기 읽기’이다. 주변 문맥을 함께 읽으면 의미를 추론할 수 있지만, 링크 목록만 사용하는 환경에서는 어느 글로 이동하는지 구분하기 어렵다. 이것만으로 WCAG 위반을 확정하지 않는다.

제안: 각 글 제목 자체를 상세 링크로 만들거나, 기존 링크의 접근성 이름에 글 제목을 덧붙인다. 전체 카드를 링크로 만들 경우 중첩 링크와 불필요한 중복 탭 정류점이 생기지 않도록 설계한다.

수용 기준: 링크 목록만으로 글 제목을 구별할 수 있고, 화면의 ‘이야기 읽기’ 문구가 접근성 이름에도 포함되어야 한다. 사진 대체텍스트와 본문을 과도하게 반복하지 않는다.

## 3. 발견 목록의 영문 장식·번호 정리

**우선순위: 중간 / 편집 디자인 제안**

근거: [discovery-content.tsx](https://github.com/jkd04255/appa-wa-ddal/blob/52b41d7f49421358ba343f7c7feedf2ca6348b9d/src/components/daughter/discovery-content.tsx)

G1-14에서 홈의 반복 영문 장식을 줄였으나 발견 목록에는 ‘SIDE B / THE DISCOVERY INDEX’와 카드별 ‘01 / 카테고리’ 표현이 남아 있다. 번호는 필터 결과의 배열 순번이어서 선택한 카테고리에 따라 바뀐다. 이는 실제 순위나 발행 번호가 아니며, 화면을 훑는 데 필요한 정보인지 검토할 여지가 있다.

제안: 상단은 ‘발견’ 같은 짧은 한국어 표기로 통일하거나 중복이면 생략한다. 카드에는 의미 있는 카테고리만 남기는 안을 비교한다. 시연·합성 콘텐츠 고지, 출처 상태 표시는 유지한다.

수용 기준: 홈 → 목록 → 상세의 제목·분류·주요 동작이 같은 어휘로 이어져야 한다. 단순 장식 제거로 실제 콘텐츠의 의미와 고지가 사라져서는 안 된다.

## 4. 모바일 ‘공간 선택’ 글자 크기 재검토

**우선순위: 중간 / 렌더링·사용자 검토 필요**

근거: [editorial-refresh.css](https://github.com/jkd04255/appa-wa-ddal/blob/52b41d7f49421358ba343f7c7feedf2ca6348b9d/src/app/editorial-refresh.css), [globals.css](https://github.com/jkd04255/appa-wa-ddal/blob/52b41d7f49421358ba343f7c7feedf2ca6348b9d/src/app/globals.css)

개편 CSS에서 모바일 공간 전환 링크는 11px이며 테두리 없이 밑줄로 표시된다. 기본 스타일의 최소 높이 44px는 유지되므로 ‘터치 영역이 44px보다 작다’고 판단할 근거는 없다. 검토할 부분은 글자 가독성과 전환 기능의 발견 가능성이다.

제안: 현재 브랜드 헤더를 유지하며 13–14px 후보를 비교한다. 버튼 외형을 크게 추가하기 전에 글자 크기·간격부터 조절한다.

수용 기준: 320/360/390px와 글자 확대 상태에서 브랜드·전환 링크가 겹치지 않아야 한다. 터치 높이 44px 이상, 키보드 초점, 역할별 4탭을 보존한다.

## 5. ‘동작 줄이기’에서 랜딩 카드 이동 제거 검토

**우선순위: 낮음 / 정적인 위치 변화 확인, 애니메이션 미차단으로 과장 금지**

근거: [globals.css](https://github.com/jkd04255/appa-wa-ddal/blob/52b41d7f49421358ba343f7c7feedf2ca6348b9d/src/app/globals.css), [editorial-refresh.css](https://github.com/jkd04255/appa-wa-ddal/blob/52b41d7f49421358ba343f7c7feedf2ca6348b9d/src/app/editorial-refresh.css)

기존 prefers-reduced-motion 규칙은 transition/animation 시간을 0.01ms로 줄이고 있다. 따라서 개편 CSS가 일반 전환 시간을 다시 설정해도 !important 규칙이 우선한다. 다만 카드 hover의 translateY(-3px) 자체는 남아 거의 즉시 위치가 바뀐다.

제안: 동작 줄이기 설정에서는 translateY도 없애고 테두리 등 정적인 변화만으로 반응을 표시하는 안을 검토한다. 현재 상태를 ‘애니메이션 설정이 전혀 적용되지 않음’으로 보고하면 부정확하다.

수용 기준: reduce 설정에서 포인터를 올려도 카드 위치가 변하지 않고, 초점·선택 인지는 유지되어야 한다. 일반 설정의 기존 반응은 별도로 판단한다.
