> 프로젝트: 아빠와 딸 (가칭)
> 상태: G0-02 문서 설계 검증 완료 / 코드 미작성
> 기준: 제품 요구사항 v2.0, [개발 계획서](./DEVELOPMENT_PLAN.md)
> 작성: 2026-11-10 (KST)
> 다음 게이트: G0-03 디자인 시스템과 핵심 화면 와이어프레임

## 1. 목표와 범위

이 문서는 **웹 디자이너(사용자 경험과 편집 디자인) → 웹 개발자(정보구조와 기술·안전 실현성)** 순으로 검토해 확정한 G0-02의 화면 구조, 페이지 경로, 사용 흐름과 검증 기준이다.

서비스 약속: "같은 집, 조금 다른 세상." / "우리가 몰랐던 서로의 이야기."

아빠 공간은 딸의 유행을 이해하고 **과잉 간섭하지 않는 대화의 실마리**를 제공한다. 딸 공간은 트렌드·취향·정보 자체로 방문할 가치가 있어야 한다. 둘의 연결은 당사자의 명시적 동의와 안전성 검토를 거친 **편집형 ‘서로의 시선’**에 한정한다.

**G0-02에서 할 일:** 화면 목록, 경로, 탭/메뉴, 홈 정보 우선순위, 읽기/쓰기/역할 전환 시나리오, 제품/기술 리스크 정의.

**하지 않을 일:** 컴포넌트 구현, DB/Auth 연동, 글/댓글 저장, 실제 커뮤니티 개방, 배포, 운영자·연령 인증의 미검증 구현. G0-03에서 색상·서체·간격·컴포넌트 디자인을 세부 확정한다.

## 2. 1차 검토 — 전문 웹 디자이너 관점

### 2.1 v2.0을 개선한 핵심 판단

| 원래 설계의 위험 | 디자이너가 수정한 방향 | 검증할 사용자 경험 |
| --- | --- | --- |
| 홈에 많은 콘텐츠 영역을 수직으로 나열 | **한 개의 주요 이야기 + 짧은 보조 카드 + 핵심 진입점**으로 편집 | 첫 화면 5초 안에 정체성과 다음 행동을 이해 |
| 두 역할 선택이 곧 로그인처럼 보일 위험 | "둘러볼 공간 선택"으로 표시, **계정 인증과 분리** | 역할 전환이 권한 인증으로 오해되지 않음 |
| 딸 홈의 ‘아빠’ 콘텐츠가 주제를 잠식 | 딸 홈은 관심사·쇼핑·문화 우선, 아빠 콘텐츠는 서로의 시선/편집 카드 내부 | 딸 공간 자체의 매력 확보 |
| 아빠 홈이 길고 설명 많은 교육 사이트처럼 보임 | 읽기 쉬운 브리핑·예시·핵심 요약 위주 | 피로 없이 한 주제 이해 |
| 인기순·공감·투표 수치가 실제 수치로 오인 | **데모 표시**, 시연 수치는 실통계와 구별 | 가짜 인기/세일 오인 방지 |
| 역할별 하위 메뉴가 지나치게 많음 | 모바일 4개 탭, 나머지 메뉴는 홈 카드/상세 페이지로 진입 | 탭 목적이 중복되지 않음 |
| 전형적 ‘아빠=네이비/딸=핑크’ 고정관념 | 정보 밀도·사진 비율·편집 리듬으로 차별화, 딸 공간의 단색 핑크 지양 | 진부하지 않은 성숙한 브랜드 |
| 상대방 의견을 원문으로 인용해 사연을 찾을 수 있음 | 동의를 얻은 **익명 편집·집계형 비교**, 원문 검색/연결 불가 | 안전한 공감 구조 |

### 2.2 모바일 홈의 정보 우선순위

**아빠 홈 (접근성 우선, 차분한 매거진)**
1. 헤더: 브랜드 + ‘아빠의 공간’ + 공간 선택/서비스 정보 메뉴.
2. 히어로 카드 1개: 오늘의 핵심 트렌드(실제 데이터 아닐 경우 '시연 콘텐츠').
3. 짧은 트렌드 4개: 사진·키워드·한 줄 핵심, 전체 보기는 ‘트렌드’.
4. 1분 브리핑: 이번 주 요약 2~3개와 상세 이동.
5. 커뮤니티 입구: 대표 주제·게시판 바로가기(**데모**).
6. ‘서로의 시선’ 카드 1개 + ‘대화 소재’ 바로가기.
7. 고정 하단 탭 4개.

**딸 홈 (에디토리얼 피드, 취향 정보 중심)**
1. 헤더: 브랜드 + ‘딸의 공간’ + 공간 선택/정보 메뉴.
2. 화제 콘텐츠 사진형 히어로 1개(시연 표기).
3. ‘발견’ 관심 카테고리 선택 칩과 사진 중심 피드.
4. 쇼핑/세일 큐레이션: **공식 확인 자료가 없으면 현재 할인으로 표시하지 않고 데모**.
5. 익명 커뮤니티 입구(글은 전부 합성 데모)와 주간 질문 카드.
6. ‘서로의 시선’ 입구는 홈 하단에 작고 자연스럽게.
7. 고정 하단 탭 4개.

**텍스트 원칙:** 카드에서는 제목 1~2줄 + 핵심 안내 1줄. 출처·날짜·상세 맥락은 상세에서 제공. 과도한 CTA·툴팁·배너 제거. 빈 상태와 오류 상태는 짧고 분명한 문장으로 표현.

### 2.3 디자인 검증 요구 (G0-03에서 구체화)

- 모바일 우선 가로 320, 360, 375, 390, 430px, 태블릿 768px, 데스크톱 1024px 이상 검토.
- 접근성 목표 WCAG 2.2 AA. 일반 텍스트 대비 최소 4.5:1, 큰 텍스트 3:1, 44×44px 이상의 터치 영역을 제품 권장 기준으로 사용. 키보드 포커스 가시성.
- 본문 글자 16px 미만을 남용하지 않고, 아빠 화면은 더욱 편안한 본문 크기·줄간격.
- 시스템 글자 확대(200%), 긴 한글 제목, 줄바꿈, 고정 하단 탭/안전 영역, 키보드 등장, 접근성 모션 감소 지원.
- 이미지는 저작권·초상권/사용권 검토. 품질 저하·로딩 느림을 피하려 이미지 비율·지연 로딩·대체 텍스트 정의.
- 실제 브랜드 컬러/타이포 및 컴포넌트 토큰은 **G0-03에서 결정**. 현재 색상은 방향성이지 확정 디자인이 아님.

## 4. 내비게이션과 사용자 이동 흐름

### 4.1 모바일 4탭

| 탭 위치 | 아빠 | 경로 | 딸 | 경로 |
| --- | --- | --- | --- | --- |
| 1 | 홈 | \`/dad\` | 홈 | \`/daughter\` |
| 2 | 트렌드 | \`/dad/trends\` | 발견 | \`/daughter/discover\` |
| 3 | 커뮤니티 | \`/dad/community\` | 커뮤니티 | \`/daughter/community\` |
| 4 | 서로의 시선 | \`/dad/perspectives\` | 서로의 시선 | \`/daughter/perspectives\` |

- 상세 화면은 모(母) 탭 활성 상태를 유지하고 ‘뒤로’를 분명히 제공.
- 공간 전환은 헤더 메뉴를 거쳐 **상대 역할 홈**으로 이동. 전환 애니메이션/모달은 최소화.
- 공통 랜딩 복귀는 항시 가능, 브라우저 뒤로 가기·새로고침·직접 링크는 정상 처리.
- 하단 탭은 페이지 콘텐츠를 덮거나 키보드/안전 영역과 충돌하지 않아야 함.

### 4.2 핵심 동선

**F-01 역할 선택**
- 첫 방문 → 랜딩 → 아빠 또는 딸 카드 → 각 홈.
- 재방문 → 마지막 공간 안내 또는 홈 연결: 자동 건너뛰기는 첫 사용자에게 혼란이 될 수 있으므로 G0-04에서 저장/복귀 UX 확정.
- 마지막 선택 공간의 브라우저 저장은 **편의 상태**만. 연령/성별/가족관계/작성 권한 아님.
- 역할 전환 시 서로의 비공개 게시판 내용 또는 초안이 새 역할에 노출되지 않음.

**F-02 아빠의 트렌드 이해**
- 아빠 홈 → 오늘의 카드 → 트렌드 상세 → 핵심 설명 → 유행 이유 → 알아두면 좋은 점 → 가벼운 대화 예시 → 공식 출처/확인일 → 뒤로.
- '이렇게 말해 보세요'를 의무/훈계로 만들지 않음.

**F-03 딸의 관심사 탐색**
- 딸 홈 → 발견 탭 → 카테고리 필터 → 상세.
- 공식 확인된 세일: 카드 → 상세 → 확인일/기간/조건/출처. **만료된 할인은 진행 중으로 표시하지 않음**.
- 직접 방문 가치가 없는 '아빠와의 소통 미션'을 딸 홈 주요 CTA로 배치하지 않음.

**F-04 두 커뮤니티 시연**
- 공간별 커뮤니티 목록 → 검색/카테고리/정렬 → 샘플 상세/댓글 → 신고 UI(시연).
- '글쓰기' → 명확한 '데모입니다 / 실제 저장되지 않습니다' 고지 → 시연 입력/취소.
- 역할 UI 전환만으로 쓰기 허가가 발급되지 않음. **G2 전에는 서버에 사용자 데이터 미저장**.
- 실제 기능은 안전 운영·연령 기준·게시판 권한을 검증하기 전 공개 금지.

**F-05 서로의 시선**
- 어느 공간에서든 4번 탭 → 같은 주제의 편집 콘텐츠 → 본문에서 다양한 관점 확인.
- 역할별 내비게이션만 다르고 **같은 콘텐츠 ID**를 사용. 원문 링크/원래 게시자/세부 인구통계 노출 금지.
- 소수 응답·소수집단 역추론 위험이 있는 집계는 표시하지 않음. '전체 10대/전체 아빠의 생각' 같은 일반화 금지.

## 5. 2차 검토 — 전문 웹 개발자 관점

### 5.1 기술 구현 순서 검토

- Next.js App Router + TypeScript + Tailwind를 **제안**한다. G1-01에서 버전 고정과 린트/타입/빌드 환경 검증 후 확정.
- \`app/(public)/page\`, \`app/dad/...\`, \`app/daughter/...\` 경로 그룹 후보를 사용하되, 불필요한 추상화는 피함.
- 공통 UI: Header, BottomNavigation, EditorialCard, DemoLabel, SourceMeta, EmptyState. **도메인 컴포넌트와 접근 정책은 공유를 강제하지 않는다**.
- 역할별 데이터를 합성 파일 또는 읽기 전용 상수로 제공. 소셜 게시물·투표·할인에 실제처럼 보이는 유효 수치를 만들지 않는다.
- 세일 정보에는 최소 \`verifiedAt\`, \`expiresAt\`, \`sourceUrl\`, \`status\`(demo/verified/expired) 정의. 모르면 '진행 중'이라고 출력하지 않는다.
- 첫 화면은 과도한 JS/동영상 자동재생/여러 UI 캐러셀을 피하고, 이미지 최적화·지연 로딩·안전한 공식 링크를 원칙으로 한다.
- Phase 1에서는 Supabase 클라이언트 연결·세션 쿠키·실DB/실사용자 업로드를 추가하지 않는다.

### 5.2 보안·권한 실현성 검토 (G2를 위한 사전 결정)

| 문제 | 채택하는 설계 원칙 | 적용 단계 |

**역할 검증에 관한 중요한 현실 제약:** 자기신고식 "아빠/딸" 버튼으로는 실제 보호자/청소년 여부를 증명할 수 없다. 대체 인증·운영비·개인정보 수집 최소화·합법성을 검토하기 전, 서버에 ‘검증된 아빠만 작성’이라는 보장을 할 수 없다. 따라서 Phase 1은 **합성 시연**, G2는 **정책 검증과 폐쇄 테스트**를 먼저 진행하며, 검증 불가 시 역할 전용 게시판의 공개 쓰기 기능을 보류한다.

### 5.3 데이터 경계 초안 (아직 DB 스키마 아님)

- **Public editorial:** 트렌드·발견·세일의 제목, 요약, 카테고리, 출처 URL, 원본일/확인일/만료일/승인 상태/대상 공간.
- **Private account:** 최소 운영 계정 ID, 별도 연령 적격/동의·검증 상태 및 접근 정책; 공개 프로필에 계정 식별자 노출 금지.
- **Role community (private by default):** 역할별 글·댓글·신고·검토·제재. 서버가 읽기/쓰기 권한 검사; 다른 역할 공간 원문 직접 조회 금지.
- **Cross-space editorial:** 별도의 편집 주제/공개 동의 기록/승인된 요약·집계; 원본 글과의 공개 링크·검색 가능 인용 금지.
- **Phase 1 local-only:** 데모 콘텐츠 정적 상수 + 역할 UI 선택 상태만 브라우저 저장 가능. 실사용자 글은 로컬스토리지에도 보관하지 않고 리로드 시 사라짐.

### 5.4 기술/품질 인수 조건

- 경로 이름이 충돌하지 않고, 4탭과 상세·직접 URL·뒤로 가기 흐름이 모순되지 않음.
- **로딩/빈 화면/유효기간 종료/출처 누락/잘못된 URL**에 대한 UI 상태 정의.
- 역할 전환·새로고침·딥 링크 시 접근 정책과 UI 상태가 섞이지 않음.
- Phase 1에서 서버 쓰기 요청·개인정보·API 비밀키·외부 추적기를 사용하지 않음.
- G1 단위별 lint, typecheck, build, 브라우저 키보드/모바일 검증. G2에선 RLS/서버 권한 부정 테스트 및 신고 운영 검증 추가.
- 스크린 리더 레이블·시맨틱 제목·모션 감소·터치 영역·텍스트 확대를 수용하는 구조.
- 관리자 승인 없이 웹 수집 내용을 자동 공개하지 않음.
