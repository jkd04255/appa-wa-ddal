# G0-03 모바일 와이어프레임 · 정보 배치 명세 v1.0

> 문서 전용, 구현 코드·렌더링 이미지 아님  
> 근거: [개발 계획서](./DEVELOPMENT_PLAN.md), [G0-02 IA](./INFORMATION_ARCHITECTURE.md), [G0-03 디자인 시스템](./DESIGN_SYSTEM.md)  
> 작성: 2026-11-10 (KST) · 상태: 화면 **구조 설계** 완료 / 브라우저·실기기 미검증

## 1. 와이어프레임 공통 규칙

- 기본 대표 뷰포트: **390×844px**. 320/360/375/430px에서 재배치 가능해야 한다.
- 320px 좌우 여백 16px(내용 폭 288px), 360px 이상 모바일 좌우 20px.
- 세로 흐름은 스크롤하며 **고정 하단 탭만 화면 하부에 위치**. 랜딩에는 공간 선택 버튼 외에 하단 탭이 없다.
- 아래 도면의 [사진]은 허가된 실제 사진이 아닌 **위치 표시자**다.
- 복잡한 툴바, 광고 배너, 여러 슬라이드, 불필요한 긴 설명을 첫 화면에 두지 않는다.
- 화면의 순서와 레이블은 G0-02 사이트맵과 일치해야 한다.
- 시연 콘텐츠·합성 커뮤니티 글·가상 투표는 실제 수치/혜택으로 읽히지 않게 구분한다.
- 도면은 세로 스택의 **상대적인 배치**를 설명한다. 문자 아트의 가로 글자 수가 실제 px 치수는 아니다.

### 화면 요소 표기
- [텍스트]: 제목/레이블/콘텐츠 예시
- [사진 자리]: 사진 자산 확보 전 시각 비율 자리
- [카드]: 탭 가능한 콘텐츠
- [시연]: 실제 유행·할인·응답·게시글이 아닌 합성 샘플
- 하단 탭: 이동 수단. 인증·사용자 계정의 역할 권한이 아님.

## 2. W-01 랜딩 (/)

**핵심 목표:** 공간 하나를 바로 선택. ‘역할 검증 화면’이 아니라 ‘둘러볼 콘텐츠 공간 선택’임을 명확히 한다.

~~~text
┌────────────────────────────────────┐
│ 아빠와 딸                           │ ← 로고/브랜드
│                                    │
│                                    │
│ 같은 집,                           │
│ 조금 다른 세상.                     │ ← 큰 한글 2~3행
│                                    │
│ 우리가 몰랐던 서로의 이야기.        │
│ 어떤 공간을 둘러보시겠어요?         │
│                                    │
│ ┌────────────────────────────────┐ │
│ │ 아빠로 들어가기                │ │
│ │ 우리 딸의 세상이 궁금하다면     │ │ ← 카드/링크
│ │                          ↗     │ │
│ └────────────────────────────────┘ │
│                                    │
│ ┌────────────────────────────────┐ │
│ │ 딸로 들어가기                  │ │
│ │ 내 취향과 이야기가 모이는 곳    │ │ ← 카드/링크
│ │                          ↗     │ │
│ └────────────────────────────────┘ │
│                                    │
│ 선택은 공간 탐색용입니다.          │
│ 실제 연령·가족관계 인증이 아닙니다. │
│                                    │
│ 서비스 소개 · 안전 안내             │
└────────────────────────────────────┘
~~~

### 레이아웃 계약
- 화면 상단 브랜드 → 카피 → 2개 선택 카드 → 작은 안내. 카드 전체를 하나의 링크로 구성.
- 랜딩에는 아이돌·제품·아빠/딸 전형적 스톡 이미지를 강제하지 않는다. **큰 타이포와 2개 카드만으로 완성**한다.
- 첫 방문의 역할을 사전에 추측하지 않는다.
- 마지막 방문 공간의 기록이 있는 경우, 카드가 기존과 동일하게 노출되며 해당 카드를 ‘지난번 선택’으로 약하게 표기할 수 있다. **첫 화면 자동 건너뛰기는 보류**.
- 이전 화면으로 되돌아와도 선택 카드 재사용 가능.
- 카드 터치 타깃 44px 이상; 두 카드 사이 최소 12px 간격.

### 작은 화면(320px) 대응
- 메인 카피 34~36px에서 실제 줄바꿈 확인. 브랜드와 카피 위아래 여백을 조정하되 카피는 삭제하지 않음.
- 선택 카드 텍스트 길이에 따라 카드 높이가 증가하도록 설계; 두 선택 카드가 항상 동등한 중요도로 보이게 한다.
- 세로가 짧은 기기에서는 스크롤 허용, 화면 높이에 맞춘 강제 축소 금지.
- 푸터 정보는 접힐 수 있지만 안전 안내 경로는 사라지지 않는다.

## 3. W-02 아빠 홈 (/dad)

**목표:** 트렌드 하나를 쉽게 이해하고, 나머지 4개를 훑어보고, 원하는 섹션으로 이동. ‘딸과 대화 미션’처럼 느껴지지 않도록 한다.

~~~text
┌────────────────────────────────────┐
│ 아빠와 딸       아빠의 공간   [⋯]  │ ← 헤더/공간 이동
├────────────────────────────────────┤
│ 오늘의 딸 트렌드                    │
│ [사진 자리 16:10]                  │
│ [시연 콘텐츠]  [카테고리]          │
│ 오늘의 가장 주목받는 이야기         │
│ 한 줄로 이해하는 문화·취향 설명    │
│                 자세히 보기        │ ← 주요 히어로 1개
│                                    │
│ 함께 보면 좋은 트렌드              │
│ [썸네일] 짧은 제목 A               │
│           한 줄 설명              │
│ [썸네일] 짧은 제목 B               │
│           한 줄 설명              │
│ [썸네일] 짧은 제목 C               │
│           한 줄 설명              │
│ [썸네일] 짧은 제목 D               │
│           한 줄 설명              │
│                    트렌드 전체보기 │
│                                    │
│ 아빠의 1분 브리핑                  │
│ [이번 주 이야기 1]                │
│ [이번 주 이야기 2]                │
│                     브리핑 보기    │
│                                    │
│ 아빠들의 이야기                    │
│ [샘플 게시글] [샘플 게시글]        │
│                 커뮤니티로 이동    │
│                                    │
│ 궁금한 질문 · 이번 주 대화 소재    │
│ [질문 보기]       [소재 보기]      │
│                                    │
│ 서로의 시선                        │
│ [동의·편집된 관점 비교 카드]       │
│                         살펴보기   │
├────────────────────────────────────┤
│ 홈  │ 트렌드 │ 커뮤니티 │ 서로의 시선│ ← 고정 4탭
└────────────────────────────────────┘
~~~

### 상세 사양
- 헤더에는 계정/인증처럼 보이는 인물 아바타를 만들지 않는다. 공간 이동/랜딩 복귀는 텍스트 메뉴로 노출.
- 히어로의 이미지 및 텍스트는 **서로 다른 영역**. 텍스트를 실제 사진에 겹치지 않게 한다.
- 오늘의 트렌드 5개: 히어로 1 + 보조 4. **첫 화면에 5장을 모두 같은 크기로 펼치지 않는다.**
- 데모에서 ‘오늘’이라는 제목은 콘텐츠 예시의 구조상 명칭이며 **실제 오늘 최신 SNS 데이터라는 보장을 뜻하지 않는다**. 카드마다 ‘시연 콘텐츠’ 표기.
- 목록 제목은 1~2줄, 메타 정보·사진 출처·알아두면 좋은 점·대화 예시 상세 페이지로 이동.
- 커뮤니티 미리보기는 실제 게시글이 아닌 샘플. 작성 권한을 보유한 것처럼 표현하지 않는다.
- 섹션 사이 32~40px, 섹션 내 카드 12~16px. 하단 탭과 콘텐츠가 겹치지 않도록 padding-bottom 확보.

### 사용자 동선 점검
1. / → ‘아빠로 들어가기’ → /dad.
2. 히어로 터치 → /dad/trends/[slug] → 뒤로 → /dad.
3. 하단 트렌드 터치 → /dad/trends.
4. 카드/헤더에서 커뮤니티·서로의 시선/랜딩 복귀 가능.
5. 브라우저 뒤로 및 새로고침 후도 해당 경로의 맥락 유지.

## 4. W-03 딸 홈 (/daughter)

**목표:** 자기 취향의 콘텐츠를 먼저 발견. 아빠 관련 콘텐츠는 부담 없는 연결로만 배치.

~~~text
┌────────────────────────────────────┐
│ 아빠와 딸       딸의 공간     [⋯] │
├────────────────────────────────────┤
│ 지금 핫한 이야기                   │
│ ┌────────────────────────────────┐ │
│ │                                │ │
│ │        [사진 자리 4:5]         │ │ ← 크게 한 장
│ │                                │ │
│ └────────────────────────────────┘ │
│ [시연 콘텐츠] [카테고리]          │
│ 지금 함께 보는 이야기 제목         │
│                 콘텐츠 살펴보기    │
│                                    │
│ 관심 있는 이야기                   │
│ [뷰티] [먹거리] [아이돌] [전체]    │ ← 4개 이내 진입
│                                    │
│ 발견                               │
│ [사진] 짧은 제목 A                 │
│ [사진] 짧은 제목 B                 │
│ [사진] 짧은 제목 C                 │
│                         더 발견하기 │
│                                    │
│ 쇼핑·세일 소식                    │
│ [데모/확인일 표시 + 정보 카드]     │
│     기간·조건은 상세에서 확인      │
│                                    │
│ 친구들과 나누는 이야기             │
│ [샘플 커뮤니티 글 1~2개]          │
│                 커뮤니티로 이동    │
│                                    │
│ 이번 주 질문                       │
│ [시연 투표 안내 / 살펴보기]        │
│                                    │
│ 서로의 시선                        │
│ [편집된 공통 질문 카드]            │
│                         살펴보기   │
├────────────────────────────────────┤
│ 홈   │ 발견 │ 커뮤니티 │ 서로의 시선│
└────────────────────────────────────┘
~~~

### 상세 사양
- 사진은 4:5로 존재감을 주지만 **사진만 띄우고 기능을 숨기지 않는다**. 카테고리와 제목은 사진 아래.
- 홈의 관심사 칩은 대표 3개 + 전체보기 정도로 간소화. 발견 페이지에서 전체 카테고리를 제공하고 홈에 7개를 한 번에 밀집 배치하지 않는다.
- 발견 피드는 콘텐츠 카드 단위로 계속 탐색 가능. 초기에 영상 자동재생, 무한 루프 슬라이더, 무분별한 인터랙션 지양.
- 공식 확인이 없는 ‘올영 세일’ 정보를 실시간 할인으로 표시하지 않는다. 데모임을 카드에 직접 표기.
- 딸 홈에서 ‘아빠들의 속마음’은 독립 대형 섹션으로 강요하지 않는다. 필요하면 ‘서로의 시선’ 아래 연결한다.
- 동년배의 실제 자유 게시판처럼 보이더라도 Phase 1은 **시연 콘텐츠**. 민감 고민은 합성·비식별 예시로 한정.
- 줄 수가 부족할 때 사진 일부 크롭보다 제목/카테고리/CTA의 읽기 우선. 모바일 긴 제목 높이 확장 허용.

### 사용자 동선 점검
1. / → ‘딸로 들어가기’ → /daughter.
2. 홈 히어로/발견 카드 → /daughter/discover/[slug] → 뒤로 → 이전 위치.
3. 쇼핑 카드 → /daughter/sales/[slug] → 공식 정보 확인일/만료 표시.
4. 커뮤니티/투표/서로의 시선 진입은 분명한 링크로. 실 저장은 없음.
5. 아빠로 전환하는 UI는 제공하지만 **작성 권한을 새로 부여하지 않음**.

## 5. W-04 모바일 하단 내비게이션

~~~text
아빠:  [홈]   [트렌드]   [커뮤니티]   [서로의 시선]
딸:    [홈]   [발견]     [커뮤니티]   [서로의 시선]

구조: 가용 폭을 4등분하여 각 아이콘과 라벨을
      세로 정렬. 활성 탭에 색상 + 텍스트/모양 변화.
      Safe area의 바닥까지 배경은 확장,
      실제 터치 영역과 글자는 안전 영역 안에 배치.
~~~

- 하단 탭 높이: 가시 영역 약 60~68px + safe area. 320px에서 각 탭 폭 약 72px(내용 폭 288px 기준)이므로 긴 라벨 ‘서로의 시선’의 줄바꿈/폰트 확대를 우선 점검.
- 터치 목표 44px 이상. 탭의 눌림 상태/활성 표시가 색깔만의 차이가 되지 않도록 선·채움/텍스트 무게를 함께 사용.
- 시멘틱 nav 영역, aria-label 및 현재 화면 aria-current 지원을 후속 구현에 요구.
- 하단 탭 때문에 글쓰기·로그아웃·뒤로가기 등의 버튼이 가려지지 않도록 콘텐츠 높이/안전 영역 분리.
- 키보드 등장 시에는 바닥 탭이 입력 필드를 가리지 않도록 스크롤/위치 전략을 G1에서 검증.
- 탭을 이동한 뒤 실제 계정 인증 상태가 변경되었다는 문구를 표시하지 않는다.

## 6. W-05 반응형 배치 가이드

| 뷰포트 | 랜딩 | 아빠 홈 | 딸 홈 |
| --- | --- | --- | --- |
| 320px | 세로 2카드, 여백 16px, 세로 스크롤 | 히어로 1열 + 썸네일 1열 | 큰 사진 1열 + 발견 1열 |
| 360~430px | 큰 타이포·카드 넉넉한 간격 | 트렌드 1+4, 여백 20px | 4:5 히어로 + 카드 1열 |
| 768px | 선택 카드 가로 2열 가능 | 2열 보조 트렌드, 본문 720px | 2열 발견 그리드 |
| 1024px 이상 | 중앙 정렬 2카드, 최대 1120px | 히어로 + 사이드 짧은 카드 배열 가능 | 큰 비주얼 + 2~3열 발견, 읽기 폭 제한 |

### 탭·헤더 이동 정책
- 모바일에서는 상단에 불필요한 중복 메뉴를 두지 않고, 탭 4개와 공간 선택만 유지.
- 768px 이상에서는 고정 모바일 탭을 그대로 확대하지 않고 역할별 상단 네비게이션으로 전환할 수 있다(구체 breakpoint는 G1 시각 QA 후 확정).
- 디자인 시스템 색과 구조를 유지하되 데스크톱에서 정보량을 무조건 늘리지 않는다.
- 랜딩의 2카드 가로 배치는 768px 이상에서만 검토하며 선택 중요도를 동일하게 유지.

## 7. 모션·로딩·빈 상태

| 상황 | 화면의 반응 |
| --- | --- |
| 첫 로드 | 브랜드/카피·히어로 첫 정보가 지연 없이 보이도록 설계, 장시간 글 등장 애니메이션 금지 |
| 이미지 미로드 | 자리를 예약해 레이아웃 이동 최소화, 오류시 설명 텍스트 유지 |
| 시연 글쓰기 | “실제 저장되지 않습니다” 사전·사후 안내, 입력이 사라지는 조건 명확화 |

| reduced-motion | 비필수 모션 제거, 콘텐츠 접근 영향 없음 |
