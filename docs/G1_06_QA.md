## 구현 산출물

- 아빠: `/dad/trends`에 5개 합성 트렌드 목록, 정확한 5개 `/dad/trends/[slug]` 상세. 기존 아빠 홈의 대표 카드와 보조 4개에서 각 slug 상세를 직접 열고 목록으로 복귀.
- 딸: `/daughter/discover`에 대표 발견 1개+보조 3개 목록, 정확한 4개 `/daughter/discover/[slug]` 상세. 기존 딸 홈의 카드 4개가 실제 합성 상세로 연결됨.
- `/daughter/discover?category=beauty|food|culture`는 서버에서 URL 상태만으로 항목을 선택; 새로고침과 뒤로 가기에 결과 유지. 알 수 없는/중복된 카테고리는 전체 합성 목록과 명시적 경고로 안전하게 표시.
- 상세 본문: 짧은 소개, 배경, 맥락·이해할 점, 팁, 강요하지 않는 대화/질문 예시, 자료 상태. 아빠는 절제된 블루그레이 그래픽, 딸은 기존 자체 호스팅 사진 4개+크림/베리/차콜 디자인.
- `src/data/fixtures/editorial-detail.ts`는 기존 slug 타입의 `Record`로 본문을 매핑, `src/lib/editorial-catalog.ts`는 데이터에서 정확히 일치하는 slug만 조회. 요청 문자열로 파일 경로, 검색 URL 또는 DB 쿼리를 구성하지 않음.
- `src/domain/editorial-detail.ts`의 `sourceDisplay()`는 demo를 시연 콘텐츠로, 승인되지 않은 verified/expired/unverified/unknown 상태는 모두 **정보 확인 필요**로 분기. G1에는 승인된 원본 URL·확인일·할인 시작/종료일이 없으므로 실제 검증된 기사·진행 중 할인이라고 표시하지 않음.
- 자료 메타는 **시연 콘텐츠 / 합성 시연 자료 · 외부 원문 없음 / 출처·확인 날짜: 해당 없음(가상 예시)**. 딸 사진은 콘텐츠 자체의 원문 출처가 아닌 분위기용 사진임을 별도 고지.
- 정확한 slug가 아니거나 양 공간 slug가 교차된 경우, 미구현 판매 상세는 **404**. 다른 글로 자동 대체하거나 검증된 정보로 가장하지 않음.
- 기본 Server Component로 구성. 계정·DB·쓰기 API·사용자 개인 정보·검색 기록/필터 장기 저장·외부 분석/유료 API 없음. 기존 랜딩/역할 기억·4탭/각 홈·저작권 기록·사진 4개·준비 중 커뮤니티/투표를 유지.
